# P6 Memory 实现计划

> **面向 AI 代理的工作者：** 必需子技能：使用 superpowers:subagent-driven-development（推荐）或 superpowers:executing-plans 逐任务实现此计划。步骤使用复选框（`- [ ]`）语法来跟踪进度。

**目标：** 控制面账号级跨会话事实记忆：显式记/忘工具、Run 成功后自动抽取、本地检索注入 system、设置页本人 CRUD；默认 SQLite 可交付。

**架构：** 新建 `internal/memory`（旁路 Store，仿 conversation）；主体键 = `conversation.Meta.OwnerID`（门禁关 → `local-dev`，admin → `admin`）；Engine 在 `buildMessages` 注入 Top-K；工具 `remember_fact` / `forget_fact`；Run 成功后 best-effort 自动抽取；`runtimecfg` 两个旋钮；设置页仅本人记忆。

**技术栈：** Go 1.25（本机常需 `$env:PATH = "$env:USERPROFILE\.local\go1.25.0\bin;$env:PATH"`）、SQLite FTS5 / Postgres `ILIKE`、React/Vitest。提交中文 Conventional Commits。Windows 用 `git commit -m "type: 说明"`（不要 bash HEREDOC）。**禁止** `move_agent_to_root` / 抢 `main` 的 worktree checkout。

规格：`docs/superpowers/specs/2026-09-14-p6-memory-design.md`

## 计划内写死的默认（规格留给计划）

| 项 | 默认 |
|----|------|
| 主体 | `Meta.OwnerID`；无 meta / 门禁关 → `local-dev` |
| 冲突 | **并存**新行；显式 `remember_fact` 若带相同非空 `key` 则 **覆盖**该 owner+key |
| 自动抽取时机 | 文本 ReAct 路径 `StatusSucceeded` 之后（`recordTerminalMessage` 前后均可，失败不改 Run 状态） |
| 总开关 | `Knobs.MemoryEnabled` 默认 **true** |
| 自动抽取开关 | `Knobs.MemoryAutoExtract` 默认 **true**（总开关关则全关） |
| 注入 | Top-K=**8**，块硬顶 **2000** 字符；单条正文硬顶 **500** |
| 检索 | SQLite：**FTS5**；Memory 实现：子串/词打分；Postgres：`ILIKE`（本批不做 tsvector） |
| 设置页可见性 | 仅当前主体自己的条目；**admin 也不能看其它运营** |
| 工具 HITL | **不**默认 require_approval |
| 日志 | info **禁止**完整记忆正文；事件/工具结果可短确认，args 走现有 redact |

## 数据模型（全计划统一）

```go
package memory

const (
	SourceExplicit = "explicit"
	SourceAuto     = "auto"
	MaxEntryChars  = 500
	DefaultTopK    = 8
	DefaultMaxInjectChars = 2000
)

type Entry struct {
	ID        string    `json:"id"`
	OwnerID   string    `json:"owner_id"`
	Key       string    `json:"key,omitempty"` // 可选；同 owner+key 显式写入覆盖
	Text      string    `json:"text"`
	Source    string    `json:"source"` // explicit|auto
	CreatedAt time.Time `json:"created_at"`
	UpdatedAt time.Time `json:"updated_at"`
}

type Store interface {
	Upsert(e Entry) (Entry, error)          // ID 空则新建；非空 key 覆盖同 owner+key
	Get(id string) (Entry, error)
	Delete(ownerID, id string) error        // 必须校验 owner
	List(ownerID string, limit, offset int) ([]Entry, error)
	Search(ownerID, query string, topK int) ([]Entry, error)
	// ForgetByKeyOrText：工具 forget；优先 key，否则精确 text 匹配该 owner
	Forget(ownerID, key, text string) (int, error)
}
```

SQLite 主表示例：

```sql
CREATE TABLE IF NOT EXISTS account_memory (
  id TEXT PRIMARY KEY,
  owner_id TEXT NOT NULL,
  key TEXT NOT NULL DEFAULT '',
  text TEXT NOT NULL,
  source TEXT NOT NULL,
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL
);
CREATE UNIQUE INDEX IF NOT EXISTS account_memory_owner_key
  ON account_memory(owner_id, key) WHERE key != '';
CREATE VIRTUAL TABLE IF NOT EXISTS account_memory_fts USING fts5(
  text, content='account_memory', content_rowid='rowid'
);
-- 触发器同步 FTS（实现时写全 INSERT/UPDATE/DELETE）
```

```
以下是该账号的相关长期记忆（供回答参考；不要主动向用户逐条复述清单，除非用户问起）：
- …
```

**Owner 解析：**

```go
func (e *Engine) memoryOwner(conversationID string) string {
  if conversationID == "" || e.Meta == nil { return "" }
  m, err := e.Meta.GetMeta(conversationID)
  if err != nil || m.OwnerID == "" { return "local-dev" }
  return m.OwnerID
}
```

**自动抽取：** 在 `UpdateRun(...Succeeded...)` 成功且 `MemoryAutoExtract` 后调用 `e.maybeExtractMemory(ctx, runID, owner, input, output)`：
- 另起一轮短 `Chat`（可用同一 `e.LLM`），system 要求只输出 JSON 数组 `[{"key":"","text":"..."}]`，最多 5 条，每条 ≤500 字
- 解析失败 / LLM 错：AppendEvent `memory.extract_skipped`（短错误），return
- 成功：`Upsert` SourceAuto；**不要**把完整 text 写入 info 日志

## 实现时注意

- 渠道 Run：若 `OwnerID` 为渠道 assignee，记忆挂在该控制面主体上（规格不做渠道用户记忆；不另开身份）。
- 注入块与 compaction 摘要并存；**不**把记忆写入 rolling summary。
- 工具结果与 extract 事件禁止完整大段记忆进 info 日志。
