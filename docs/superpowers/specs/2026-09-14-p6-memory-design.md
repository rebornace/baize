# P6：控制面账号级 Memory 产品化

## 1. 背景与动机

今日只有会话窗口与滚动摘要，没有「同一登录用户跨对话可管理的事实记忆」。文档问答已可用**上传工作区**或 **MCP** 接外部笔记/向量服务，不必再造知识库史诗。

产品要把 Memory 做成开源第一版的一等能力：完整（显式 + 自动抽取 + 设置页 + 本地检索），而不是分期只做记事本。

## 2. 已确认产品决策

| 议题 | 决策 |
|------|------|
| 记忆主体 | **控制面账号**（admin/operator）；同账号跨会话共享 |
| 写入 | **完整混合**：显式工具（记/忘）+ **自动抽取** + 设置页 CRUD |
| 检索 | 条多时按当前问题 **本地检索** 再注入（SQLite FTS/关键词；可选本机向量） |
| 外置向量云 | **不做** |
| 文档 / RAG | **不进 P6**；继续用上传文件或 MCP |
| 渠道用户记忆 | **不做**（微信等用户记忆后继） |
| 合并 | **独立史诗** |

## 3. 成功标准

1. 同一控制面账号在对话 A 写入的事实，对话 B 的 Run 能检索并注入相关条目。  
2. 模型可显式记住/忘记；跑完或约定时机可自动抽事实入库。  
3. 设置页可按账号查看、编辑、删除记忆；运营之间隔离。  
4. 不把用户上传的整份文档当「记忆」主路径；大文档仍走工作区/MCP。  
5. 默认单机/SQLite 可交付，不依赖外置向量 SaaS。

## 4. 范围

### 做

- 存储：按 `operator_id`（或等价控制面主体）存事实条目（文本、可选键、时间、来源：显式/自动）。  
- 工具：记住 / 忘记（或等价命名）；与现有 tool Registry 一致。  
- 自动抽取：在 Run 结束或压缩等时机抽取短事实；冲突策略为覆盖或并存 + 人工删改（实现计划写死默认）。  
- 检索：对本轮用户输入检索 Top-K 注入 system（或独立 system 块）；有上限防止撑爆上下文。  
- 设置页：列表 / 编辑 / 删除（admin 是否可看全部运营记忆：默认 **否**，仅本人；若需审计后继）。

### 不做

- 跨用户共享记忆、团队知识库、定时「记忆巩固」流水线。  
- 外置向量云、托管记忆商业能力（E 类）。  
- 渠道侧用户身份记忆。  
- 用 Memory 替代 compaction 或工作区文件。  
- 把 MCP/上传文档检索并进本史诗。

## 5. 架构草图

```
Run 结束 / 显式工具
        │
        ▼
抽取或写入事实 ──► memory store（按控制面账号）
        │
新 Run 组装 system
        │
        ▼
按当前输入检索 Top-K ──► 注入「账号记忆」块
```

与 compaction：摘要仍管「本会话过长历史」；Memory 管「跨会话稳定事实」。二者并存，不互相替代。

## 6. 风险与依赖

- 自动抽取误记 → 必须可删、可关（设置项或 agent 开关在计划中定）。  
- 注入过长 → 硬顶条数/字符。  
- Gate 关闭时的「匿名」主体：无稳定 operator_id 则 Memory 不可用或仅进程内（计划写死）。  
- 隐私：日志与事件不得打印完整记忆正文（可截断）。

## 7. 测试与验收（规格级）

- 同账号两会话：记事实 → 新会话能命中。  
- 不同 operator 隔离。  
- 显式忘记 / 设置页删除后不再注入。  
- 自动抽取可测（固定 fixture 对话）。  
- 检索 Top-K 与长度上限。

## 8. 后继（非本批）

- 渠道用户记忆。  
- 团队共享记忆与导入导出。  
- 本机向量增强或可选外置后端。  
- admin 审计全部运营记忆。
