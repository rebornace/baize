## 1. 背景与动机

开源首版确认「i18n：要做」。RUNTIME 已把设置等人话文案抽到稳定键，但 UI 仍是单一中文常量，无语言切换、无英包、无浏览器默认。完整多语言属独立史诗，本刀交付可切换的双语文案框架与全量 WebUI 英译。

## 2. 已确认产品决策

| 议题 | 决策 |
|------|------|
| 语言 | **zh-CN + en** |
| 默认 | **localStorage 优先**；无记录则跟浏览器（`zh*` → zh-CN，其余 → en） |
| 覆盖 | **全量 WebUI**：`strings.ts` 全键 + 清扫硬编码中文 |
| 偏好持久化 | **仅本机** `localStorage`；不做账号同步 / 后端偏好 API |
| 入口 | **设置**（运行参数页顶部语言区）+ **顶栏**快捷切换 |
| 方案 | **轻量 Locale + 双语文案包**（方案 A）；不引入 i18next |
| 不译 | 对话/Skill/Connector 用户内容；后端 API 错误原文；技术 id / 错误码 / hint 字段名 |
| 合并 | **独立史诗** |

## 3. 成功标准

1. 无 localStorage 时：浏览器 `zh*` 默认中文，否则英文。  
2. 写入 `baize.locale`（`zh-CN` \| `en`）后刷新仍保持。  
3. 设置页与顶栏均可切换；切换后 UI 文案即时更新；`document.documentElement.lang` 同步。  
4. 英文模式下主导航、Chat 壳、各设置页无裸中文 UI 串（§4 例外除外）。  
5. vitest / tsc / build 绿。

## 4. 范围

### 做

- `LocaleProvider`、`resolveLocale`、`localStorage` 读写。  
- `locales/zh.ts` / `locales/en.ts` 同键结构；`useStrings` / `getStrings`。  
- 消费方改走当前 pack；helper（`tierLabel`、`friendlyError` 等）吃 pack。  
- `settingsNav` 等硬编码中文迁入键。  
- 运行参数页语言区 + Chat 顶栏 chip。

### 不做

- 账号级语言、第三语言、RTL、i18next。  
- 翻译用户生成内容、Skill 正文、Connector 名/描述、模型输出。  
- 翻译服务端错误原文（仅前端已有映射键）。  
- 改设置信息架构（不新增独立「外观」导航项；语言挂运行参数页顶）。

## 5. 架构草图

```
navigator.language ─┐
localStorage ───────┼─► resolveLocale ─► LocaleProvider ─► useStrings / getStrings
设置语言区 / 顶栏 ──┘         │
                              ├─ document.documentElement.lang
                              └─ locales/zh | en（同键）
```

- 键名稳定、无中文当 key（延续 RUNTIME 附录）。  
- React 树内用 `useStrings()`；非组件路径用 Provider 同步的 `getStrings()`。

## 6. 偏好键

| 项 | 值 |
|----|-----|
| Storage key | `baize.locale` |
| 合法值 | `zh-CN` \| `en` |
| 非法/空 | 忽略，回退浏览器探测 |

## 7. 测试与验收（规格级）

- `resolveLocale`：storage / 浏览器 / 回退矩阵。  
- Provider：切换后 `lang` 与抽样文案变化。  
- 同键：en 与 zh 结构一致（类型或测试）。  
- 回归：既有 strings / 设置页测在 Locale 包装下仍绿。
