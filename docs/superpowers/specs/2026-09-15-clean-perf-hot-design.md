## 1. 目标

用**可复现**的本地探针建立四条热点路径的基线；仅当前后对比**差异显著且不伤可读性**时做小改动；有可追溯数字才回填产品 README（中/英）。无显著收益则记录「已测、保持现状」，不编造竞品对比。

## 3. 探针范围（四条，全做）

| # | 路径 | 探针意图 | 约束 |
|---|------|----------|------|
| A | 聊天流式 `GET /v0/runs/{id}/stream` | 计时首事件 / 终端事件；可基于现有 SSE 测试或 demo HTTP | 本地；可脚本化 |
| B | 会话消息读写 | 可控 N 条消息下 list / store 路径耗时 | `go test` 计时或轻量 `Benchmark`；非集群压测 |

| D | 渠道出站 | outbound-deliveries 列表/重试或 webhook 出站 fixture | **禁止**打真实外网 |

## 5. 「显著差异」裁定（实现计划细化阈值）

- 默认以**同机同命令重复 ≥3 次**的中位数对比；优化后相对改善建议 **≥20%** 或绝对延迟对体感有明确价值，才值得改代码。  
- 低于阈值：笔记写「已测、保持现状」，**不**为刷数字改代码。  
- 禁止：无基线的「感觉优化」、伪造竞品碾压、把偶发抖动写成成果。

## 7. 验收（DoD）

1. 四条探针均可由文档中的命令复现；笔记含环境与摘要。  
2. 若有代码优化：附前后数字与触及测试绿。  
3. README 每个数字可追溯到笔记/脚本输出；无数字则写清「已测、保持现状」或保留待测说明的诚实表述。  
4. `go test` 相关包与 `web/chat` lint/test/tsc 按仓库惯例绿。  
5. 账本：PERF-HOT **已交付**；CLEAN 史诗收口或标明收尾。

## 8. 风险

- Windows 本机计时抖动：用中位数 + 注明硬件/Go 版本。  
- demo/mock LLM 与真实 LLM 延迟不可比：README **只声称本地探针环境**，不外推生产 SLA。
