# 消息回调 / 外部来信：结果导向文案与信息层级

- 日期：2026-09-13
- 状态：已交付（2026-09-13）
- 归属：WebUI 体验改版后续；承接「消息组人话化」已交付后的文案深度迭代
- 方法：方案 B（结果导向）+ 范围 2（文案 + 信息层级），已批准

## 1. 背景与产品依据

上一里程碑（`2026-09-13-messaging-settings-humanize-design.md`）完成了中文标题、P3 原语与交互壳，但主界面说明仍偏集成文档口吻（引擎并行、HMAC、POST、5xx/死信、`KEY=VALUE` 等）。

产品依据：

- WebUI 改版总规格：`2026-09-09-webui-experience-refresh-design.md` — **零术语、普通人可读；技术细节默认隐藏、按需展开**。
- 角色：管理员配置能力；运营是日常使用者，但对消息回调 / 外部来信为 **locked（不可进、不可改）**。
- 开源无法假定持有管理员口令者懂技术 → **这两页文案按非技术管理员书写**；协议细节归技术文档。
- 补充原则：能白话则白话；去掉后操作明显变难、又无法用交互弥补的，可保留必要专业词（如「地址」「密钥」）。
- **界面文案不出现产品名**（如「白泽」/ Baize），项目可能更名；用「这里 / 本系统 / 对话」等通用说法。

## 2. 目标与成功标准

**目标：** 主界面只回答「做什么 / 填什么 / 通不通」；协议、格式细则、重试状态码策略收入折叠或文档链接。

**成功标准：**

1. 未展开「给技术人员」/「高级」时，主界面看不到：HMAC、POST、5xx/4xx/429、`KEY=VALUE`、引擎/实时流、正则或字符集细则、README 协议图话术。
2. 管理员仍能独立完成：消息回调的保存 / 发送测试 / 查看失败并重试；外部来信的添加通道、复制地址、更换密钥、发送测试、删除并保存。
3. 必要操作词可保留：地址、密钥、保存、发送测试、重试（或「再试一次」）。
4. 不改后端 API / ACL / 路由 id；运营 locked 行为不变。
5. UI 字符串无产品名硬编码；相关 vitest 更新；`tsc` / 测试绿；重建 `internal/ui/dist`。

## 3. 已确认决策

1. 范围：**文案 + 信息层级**（非仅软改写、非配置/排查两区默认收起投递列表）。
2. 强度：**方案 B 结果导向**。
3. 「死信」主界面改为运营可懂状态语；技术原词可放在折叠详情。
4. 投递列表**保持可见**（不默认整区隐藏），用文案降噪而非方案 C。
5. 不出现产品名。

## 4. 文案原则

1. 主路径讲结果与动作，不讲协议实现。
2. 格式与重试规则 → 「给技术人员」或字段折叠；不挡保存/测试。
3. 校验失败用人话 inline；不展示正则原文。
4. Toast 成功句简洁；避免堆 `run=` / `delivery=` 技术片段（细节可放 Toast detail 或折叠）。

## 5. 消息回调（`/settings/webhooks`）

布局保持：上配置、下「最近通知/投递」列表。

| UI 元素 | 定稿文案 |
|---------|----------|
| 页标题 | 消息回调（与导航一致） |
| 副标题 | 有消息或任务结束时，自动通知你填的网址。这不是连接里的「企业统一执行地址」。 |
| 地址标签 | 通知地址 |
| 地址 hint | 留空表示不发送通知 |
| 请求头标签 | 请求头（保留；对接时常必要） |
| 请求头 hint | 一般不用填；有对接文档时按文档填写 |
| 保存 / 测试 | 保存；发送测试 |
| 列表标题 | 最近通知 |
| 列表说明 | 可查看未发出或多次失败的通知，并可重试。 |
| 空列表 | 暂无待发送或已停止的记录。 |
| 状态：原 dead | 已停止（多次失败） |
| 状态：pending | 等待发送 |
| 状态：delivered | 已发送 |
| 重试按钮 | 重试（或「再试一次」，实现时择一并测） |
| 折叠「给技术人员」 | 请求头每行格式 `KEY=VALUE`；重试策略（网络错误、5xx、429 最多 5 次，其余 4xx 停止）；与「企业统一执行地址」的概念区分补一句。主副标题不再承载协议。 |

成功 Toast 保持短句（已保存 / 测试成功 / 已加入重试）；失败走 `friendlyError`。

## 6. 外部来信（`/settings/inbox`）

| UI 元素 | 定稿文案 |
|---------|----------|
| 页标题 | 外部来信 |
| 副标题 | 给外部系统一个专用收件地址；对方按约定发来后，会在这里变成一场对话。 |
| 空态标题 / 说明 | 还没有收件通道；添加后，告警、工单等系统就能把消息送进来。 |
| 添加 | 添加收件通道 |
| 通道名称 | 通道名称（英文）；hint：保存后不要轻易改；用来区分不同来源。格式规则不进 hint，仅校验人话。 |
| 绑定助手 | 用哪个助手处理 |
| 启用 | 启用 |
| 说明 | 备注 |
| 默认技能 | 默认带上的技能 |
| 复制地址 | 复制收件地址 |
| 更换密钥 | 更换密钥；确认：旧密钥立即失效，对方系统需换成新密钥；新密钥只显示一次。 |
| 发送测试 | 发送测试 |
| 高级：覆盖通知 | 本通道专用通知地址；hint：多数情况留空，会用「消息回调」里的全局设置。 |
| 高级：请求头 | 与消息回调一致；格式进「给技术人员」，主区 hint 不写 `KEY=VALUE`。 |
| 原「技术说明」 | 改标题为「给技术人员」；内容改为短步骤白话 + 链到现有生产集成文档；去掉主路径上的 HMAC/POST 堆砌。 |
| 密钥尾号展示 | 已设置密钥（尾号 ···xxxx），不出现裸 `secret …`。 |
| 删除确认 | 从列表去掉这个通道。若已保存过，还需再点一次「保存」才会真正删除。 |

校验人话示例：请填写通道名称；名称格式不正确；名称重复；请选择助手；请求头填写不符合对接文档要求（具体格式在折叠中说明）。

## 8. 测试与验收

- vitest：标题/副标题/状态文案/折叠存在性；校验文案；删除与更换密钥确认路径；密钥展示文案；无产品名快照或字符串断言。
- `npm test`、`npx tsc --noEmit`、`npm run build` → 更新 `internal/ui/dist`。
- 手动：未展开折叠时主界面无协议词；管理员走通配置与失败重试；运营 locked 不变。

## 9. 风险

| 风险 | 对策 |
