[![Go](https://img.shields.io/badge/Go-1.25-00ADD8?logo=go&logoColor=white)](https://go.dev/)

[![baize - Lightweight AI Agent Framework | Product Hunt](https://api.producthunt.com/widgets/embed-image/v1/featured.svg?post_id=1255168&theme=light&t=1789790934744)](https://www.producthunt.com/products/baize?embed=true&utm_source=badge-featured&utm_medium=badge&utm_campaign=badge-baize)

**面向团队的 AI 助手运行时：能对话、会调用业务系统、重要操作可先让人确认，挂在现有服务旁边就能用。**

传说中白泽通晓万物之名；我们用这个名字，希望助手也能把业务世界里的接口、插件和流程认清楚、用起来。白泽帮团队把「会思考的助手」接到已有业务上：看懂目标 → 调用接口或插件 → 需要时请运营在操作台确认 → 把结果写回对话或消息渠道。业务系统一般**不用改代码**；有接口文档就能让助手真正去执行。网页 **`/ui`** 是给产品、运营和集成同学用的操作台。

---

## 产品优势

- **接口文档变能力**：上传或指定 OpenAPI / Swagger / Postman 一类文档，接口会变成助手可调用的工具，调用过程可在操作台看见。
- **重要操作可先审批**：建单、改状态等写操作，可要求运营在卡片上点「批准」或「驳回」后再执行，过程可追溯。
- **旁挂即用、停用干净**：单独一个进程，配置放在外面；停掉之后，业务侧几乎不留痕迹。
- **同一套助手，多种入口**：操作台、告警/工单来信、即时消息渠道等，共用审批、记忆和出站能力。
- **需要登录的下游也能接**：助手可引导完成登录，再带着会话凭证去调业务系统。
- **长对话更稳**：自动压缩过长上下文；可配置多套模型、思考深度；可记账号级要点、带附件与工作文件。

## 助手能做什么

### 对话与执行

- 默认按「思考 → 选工具 → 执行 → 汇报」推进；也可用技能包里的分步流程（可含审批点）。
- 操作台可**边跑边看**助手的推理与工具步骤，过程可见。
- 多套模型配置可切换；支持调节模型「思考」相关选项（视模型能力而定）。
- 新增模型时可直接**拉取端点的模型列表批量导入**：填好服务地址（API Key 可留空，报 401 再补），一键拉取该 OpenAI 兼容端点支持的模型，勾选后批量建为模型配置；端点不支持时也可手动填写单个模型。
- **技能包**：说明文档 + 可用工具；可设默认技能，也可在本轮对话里临时启用更多技能。

### 工具从哪里来

- **接口文档一键变工具**：每个接口进入工具列表，助手可直接调用。
- **HTTP 插件（旁路小服务）**：没有完整文档、或逻辑写在文档外时，可自建一个小服务，按约定告诉白泽「有哪些工具、怎么执行」。适合封装遗留系统、内部脚本或定制逻辑。也可让白泽把「要调哪个工具、参数是什么」回调到你们自己的地址，由你们侧执行。
- **接入外部工具生态（MCP）**：白泽可作为客户端，接上支持 MCP 的工具服务（含常见的授权登录流程）。
- **把工具导出给常用 Agent 客户端**：白泽也可作为 MCP 服务端，把选定的工具目录**只读**提供给 Cursor、Claude Desktop 等支持 MCP 的助手客户端——在那些客户端里直接用你们已接好的业务能力，而不必再配一遍。导出路径不经过白泽自己的大模型对话，适合「工具目录共享」。

### 人在回路与安全

- 敏感写操作可暂停，等运营在操作台确认后再继续。
- 工具可随时停用；完整密钥不会出现在对话事件回放里。
- 试用可用内置模拟模型（不必准备云厂商密钥）；正式环境再配置真实模型，两条路径分开。

### 记忆、材料与长会话

- **记忆**：可保存账号级可检索要点，助手跨对话仍可参考。
- **附件与对象存储**：支持本地或对象存储等方式存放材料。
- **上下文压缩**：对话很长时自动做滚动摘要，把篇幅留给真正有用的信息。
- 支持会话分叉、回退等运营常用操作（操作台与接口均可）。

### 消息渠道

白泽把「渠道」做成可扩展能力：告警、工单、即时消息等都可以接到**同一套**助手、审批与出站。

- **带签名的来信入口**：外部系统把告警/工单推进来，进入同一套助手与审批。
- **即时消息**：架构上支持通过适配器对接各类 IM。**当前仓库已提供的适配器是个人微信私信**（独立小进程 + 出站队列，失败可在设置里重试）。其他 IM 可按同一方式继续适配，并不限于微信。
- 也可把事件推到你们自己的通知地址。

### 给产品、运营与集成

- 浏览器操作台支持**中文 / 英文**，含对话、工具卡片、设置与运行参数。
- 提供完整的 HTTP 管理接口，可用脚本或平台对接；不强制绑定某一种编程语言 SDK。
- 部分运行参数可热更新；默认用本地数据库即可跑起来，需要时再换更大规模的数据库。

## 典型场景

**老系统旁边挂一个助手**  
服务已在线上、暂时不改代码：旁挂白泽，用接口文档把能力交给助手，内网先试「能查、能建单、能审批」，确认价值再谈改造。

**写操作必须人点头**  
助手可以查数、起草、建议；真正改状态、发指令时，运营在操作台确认，过程留痕。

**工具与渠道收拢到一台助手**  
外部工具、自研插件、来信入口、即时消息——同一套审批与记忆，减少「每个入口各养一个机器人」。

**在常用 Agent 客户端里复用已接好的业务工具**  
在白泽里接好接口与插件后，通过 MCP 导出到 Cursor 等客户端，团队在习惯的环境里直接调用。

## 架构理念：决策层

随着接入的连接器增多，一轮对话可能携带大量工具 schema，prefill 成本也随之增加。白泽通过一个**决策层**来处理这个问题：把高频的路由判断从生成式调用中移到一个廉价、确定性的步骤。这一思路借鉴了 **Jev** 所代表的校准式决策思想；由于白泽使用 OpenAI 兼容接口、读不到 logits，因此不使用概率分数，也不依赖任何外部服务。决策层在本地、可插拔，并且始终 fail-open（失败即放行）。

当工具数超过阈值时，主模型调用前会先走一个**两级路由**：

1. **系统路由**：选出这一轮需要哪些连接器，采用混合路由——查询中有区分度的词会强制命中某个连接器，模型的选择在其上补充（不能移除被强制命中的连接器）。
2. **系统内预筛**：用确定性关键词预筛（按系统分别做 IDF，覆盖拉丁词项与中文 bigram）保留最相关的少量候选，主模型收到的是一份更短的列表。

收敛只影响「这一步 prompt 里出现哪些 schema」，**不影响工具本身能不能用**：已注册的工具只要被点名仍会执行。没有任何命中时则 fail-open 回退为全量；系统工具与登录工具始终保留。

### 基准结果（可复现）

设置：**37** 条真实只读业务请求，横跨 **3** 个已接入的后台（共 **390** 个工具），模型为 DeepSeek-Flash；稳定性连跑 **5 轮（共 185 次请求）**。语料与脚本见 [`scripts/tool-routing-eval`](scripts/tool-routing-eval/README.md)。

| 预筛收口 | 运行成功 | 平均实发工具 | 平均 turn-0 prompt | 相对收口 32 |
|---|---|---|---|---|
| 32 | 36/37 | 43.1 | 4,703 | — |
| 24 | 37/37 | 37.4 | 3,980 | −15% |
| **16（默认）** | **37/37** | 30.6 | **3,090** | **−34%** |
| 12 | 37/37 | 27.1 | 3,033 | −36% |
| 8 | 35/37 | 23.6 | 2,600 | −45% |

直接下发**全量 390 个**工具时，turn-0 实测约 **8.5 万** prompt tokens；收口 16 时实测约 **1.4k–3.8k**。连跑 **5 轮（共 185 次请求）**时，收口 16 的运行成功率为 **99.5%（184/185）**；唯一一次失败来自无关工作流，而非工具不可用。收口 8 时有两个多步请求失败。默认收口为 **16**。

决策层为**可选项**、通过运行时设置热更新（出厂默认关闭）；上表为开启工具路由后的实测表现。

## 快速开始

**环境：** Go 1.25 或更高（与持续集成一致；不必装 C 编译器），以及一个 OpenAI 兼容服务的 API Key。

```bash
cp .env.example .env        # 然后填写 BAIZE_API_KEY=sk-...
```

```powershell
.\serve.cmd                 # Windows
```

```bash
./scripts/serve.sh          # macOS / Linux
```

- 操作台：http://127.0.0.1:8080

打开操作台即可发消息。如需更换模型、Base URL 或接入业务系统，把 `configs/config.yaml` 复制为 `configs/config.local.yaml`（已 gitignore）并修改，再用 `.\serve.cmd -config configs\config.local.yaml`（或 `./scripts/serve.sh -config configs/config.local.yaml`）启动。

## 用预编译二进制部署（无需安装 Go）

适合直接在服务器或本机跑正式环境。从 [GitHub Releases](https://github.com/rebornace/baize/releases) 下载对应平台的压缩包（含 `baize` 与可选的 `weixin-adapter`），解压后按下面配置即可。

**1. 准备目录（示例）**

```text
baize/
  baize                 # 或 Windows 的 baize.exe
  weixin-adapter        # 仅使用微信渠道时需要
  configs/config.yaml   # 可从本仓库拷贝样板
  .env
  data/
```

**2. 写 `.env`（密钥不进 YAML）**

```bash
BAIZE_API_KEY=sk-你的模型密钥
BAIZE_SETTINGS_KEY=一串足够长的随机字符
# 可选：BAIZE_LISTEN=:8080
```

**3. 启动**

```bash
# 在解压目录下（使用 configs/config.yaml）
./baize serve
# 或显式指定另一份配置：
./baize serve -config configs/config.local.yaml
```

操作台：http://127.0.0.1:8080/ui  

改端口、模型地址、数据库路径等改 YAML / 环境变量后**重启进程**即可，不必重新编译。连接器、账号等多数能力可在操作台配置，写入 `data/`。

Linux 用 systemd 托管、微信适配器独立部署等，见 [部署说明](docs/developers/deployment.md)。本仓库也可用脚本本地交叉编译：

```bash
# Windows PowerShell
.\scripts\build-release.ps1 -Version v0.1.0
# macOS / Linux
./scripts/build-release.sh v0.1.0
```
