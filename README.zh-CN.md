[![baize - Lightweight AI Agent Framework | Product Hunt](https://api.producthunt.com/widgets/embed-image/v1/featured.svg?post_id=1255168&theme=light&t=1789790934744)](https://www.producthunt.com/products/baize?embed=true&utm_source=badge-featured&utm_medium=badge&utm_campaign=badge-baize)

**面向团队的 AI 助手运行时：能对话、会调用业务系统、重要操作可先让人确认，挂在现有服务旁边就能用。**

传说中白泽通晓万物之名；我们用这个名字，希望助手也能把业务世界里的接口、插件和流程认清楚、用起来。白泽帮团队把「会思考的助手」接到已有业务上：看懂目标 → 调用接口或插件 → 需要时请运营在操作台确认 → 把结果写回对话或消息渠道。业务系统一般**不用改代码**；有接口文档就能让助手真正去执行。网页 **`/ui`** 是给产品、运营和集成同学用的操作台。

---

## 产品优势

- **接口文档变能力**：上传或指定 OpenAPI / Swagger / Postman 一类文档，接口会变成助手可调用的工具，调用过程可在操作台看见。
- **重要操作可先审批**：建单、改状态等写操作，可要求运营在卡片上点「批准」或「驳回」后再执行，过程可追溯。
- **旁挂即用、停用干净**：单独一个进程，配置放在外面；停掉之后，业务侧几乎不留痕迹。
- **同一套助手，多种入口**：操作台、告警/工单来信、即时消息渠道等，共用审批、记忆和出站能力。
- **需要登录的下游也能接**：助手可引导完成登录，再带着会话凭证去调业务系统。
- **长对话更稳**：自动压缩过长上下文；可选「长对话保留重点」（只整理给模型看的要点，不改写已保存的聊天记录）；可配置多套模型、思考深度；可记账号级要点、带附件与工作文件。
- **工作区与登录**：操作台可切换工作区；同一工作区内的对话共享已登录的业务账号，工作区之间互不串号。
- **能回答白泽自己怎么用**：内置 `baize-help` 技能（中英文），问架构、设置入口、工作区与账号边界时，会引导到操作台对应页，而不会去改 `config.yaml` 或重启进程。
- **工具多也能收得住**：业务系统一多，可在设置「匹配与决策」里一键启用——匹配模型与决策模型（`tev1`）都支持本机 Ollama 或云端 / 自建 API，可共用同一台 Ollama。默认仍是无需额外组件的标准匹配，失败会自动回退。

## 助手能做什么

### 对话与执行

- 默认按「思考 → 选工具 → 执行 → 汇报」推进；也可用技能包里的分步流程（可含审批点）。
- 操作台可**边跑边看**助手的推理与工具步骤，过程可见。
- 多套模型配置可切换；支持调节模型「思考」相关选项（视模型能力而定）。
- 新增模型时可直接**拉取端点的模型列表批量导入**：填好服务地址（API Key 可留空，报 401 再补），一键拉取该 OpenAI 兼容端点支持的模型，勾选后批量建为模型配置；端点不支持时也可手动填写单个模型。
- **技能包**：说明文档 + 可用工具。设置页勾选并「保存默认配置」只影响新对话的**预激活**起点；未勾选的技能仍可在聊天用 `@`/`/`（含 `/reload` 补全）或由助手 `activate_skill` 按需加载。本轮 pin 会写到用户消息上，历史气泡旁仍可见标签。技能里列出的工具默认是保底集合（始终尽量留给模型），**不是**把未列出的连接器工具关掉；Agent 可开启**严格工具绑定**（`tool_binding: exclusive`，仍可通过 `activate_skill` 扩大）。技能库变更后下一轮会自动对齐，也可显式 `skills_reload` / `/reload`。登录类 `login-*` 技能请按需 `@login-…`，不要勾成默认。
- **工作区**：侧栏可切换 / 新建工作区；新对话落在当前工作区。v1 不把已有对话挪到别的工作区。
- 思考过程默认收成一行，点开再看全文；流式结束时用量统计会立刻写到该条回复上。

### 工具从哪里来

- **接口文档一键变工具**：每个接口进入工具列表，助手可直接调用。
- **HTTP 插件（旁路小服务）**：没有完整文档、或逻辑写在文档外时，可自建一个小服务，按约定告诉白泽「有哪些工具、怎么执行」。适合封装遗留系统、内部脚本或定制逻辑。也可让白泽把「要调哪个工具、参数是什么」回调到你们自己的地址，由你们侧执行。
- **接入外部工具生态（MCP）**：白泽可作为客户端，接上支持 MCP 的工具服务（含常见的授权登录流程）。
- **把工具导出给常用 Agent 客户端**：白泽也可作为 MCP 服务端，把选定的工具目录**只读**提供给 Cursor、Claude Desktop 等支持 MCP 的助手客户端——在那些客户端里直接用你们已接好的业务能力，而不必再配一遍。导出路径不经过白泽自己的大模型对话，适合「工具目录共享」。

### 人在回路与安全

- 敏感写操作可暂停，等运营在操作台确认后再继续。
- 工具可随时停用；完整密钥不会出现在对话事件回放里。
- 试用可用内置模拟模型（不必准备云厂商密钥）；正式环境再配置真实模型，两条路径分开。

### 记忆、材料与长会话

- **记忆**：可保存账号级可检索要点，助手跨对话仍可参考。
- **附件与对象存储**：支持本地或对象存储等方式存放材料。
- **上下文压缩**：对话很长时自动做滚动摘要（结构化检查点：目标 / 进度 / 决定 / 必须保留的事实），把篇幅留给真正有用的信息。
- **长对话保留重点**（运行参数里可选，默认关）：对话变长后，助手可把还要用的关键信息整理成给模型看的投影；失败则退回原有压缩。不承诺省云端 API token。
- 支持会话分叉、回退等运营常用操作（操作台与接口均可）。
- Web 登录身份按**工作区**共享；渠道会话（如微信）与 MCP 导出身份仍按各自隔离键。

### 消息渠道

白泽把「渠道」做成可扩展能力：告警、工单、即时消息等都可以接到**同一套**助手、审批与出站。

- **带签名的来信入口**：外部系统把告警/工单推进来，进入同一套助手与审批。
- **即时消息**：架构上支持通过适配器对接各类 IM。**当前仓库已提供的适配器是个人微信私信**（独立小进程 + 出站队列，失败可在设置里重试）。其他 IM 可按同一方式继续适配，并不限于微信。
- 也可把事件推到你们自己的通知地址。

### 给产品、运营与集成

- 浏览器操作台支持**中文 / 英文**，含对话、工具卡片、设置与运行参数；运行参数按「常用 / 智能提速 / 记忆与压缩 / 安全」分栏；「匹配与决策」单独成页（工具预筛 + 决策服务）。
- 提供完整的 HTTP 管理接口，可用脚本或平台对接；不强制绑定某一种编程语言 SDK。
- 部分运行参数可热更新；默认用本地数据库即可跑起来，需要时再换更大规模的数据库。

## 典型场景

**老系统旁边挂一个助手**  
服务已在线上、暂时不改代码：旁挂白泽，用接口文档把能力交给助手，内网先试「能查、能建单、能审批」，确认价值再谈改造。

**写操作必须人点头**  
助手可以查数、起草、建议；真正改状态、发指令时，运营在操作台确认，过程留痕。

**工具与渠道收拢到一台助手**  
外部工具、自研插件、来信入口、即时消息——同一套审批与记忆，减少「每个入口各养一个机器人」。

**在常用 Agent 客户端里复用已接好的业务工具**  
在白泽里接好接口与插件后，通过 MCP 导出到 Cursor 等客户端，团队在习惯的环境里直接调用。

## 架构理念：决策层与匹配

随着接入的连接器增多，一轮对话可能携带大量工具 schema，prefill 成本也随之增加。白泽通过一个**决策层**来处理这个问题：把高频的路由判断从生成式调用中移到一个廉价、确定性的步骤。这一思路借鉴了 **Jev** 所代表的校准式决策思想。

**启用方式（两步）：**

1. 设置「**匹配与决策**」一键启用 **System One** 决策模型：本机 **Ollama ≥0.35** 自动拉取 **`tev1`**（纯 CPU 友好），或对接云端 / 自建 API（统一 `POST /v1/systemone`）。国内一键安装优先走 [ModelScope 社区同步源](https://www.modelscope.cn/models/Lixiang/ollama-release/files)（跟 GitHub 发版标签同步），失败再试其他镜像。
2. 在「**运行参数 → 智能提速**」打开总开关，并按需打开子功能（工具候选收敛、工具结果剪枝、记忆预判、长文选档等）。**只配决策模型、不打开总开关与对应功能，不会省主模型 token。**

判定链路顺序：**System One → 备用模型（`decide_profile_id`，可选）→ Rules**。已配 System One 时，备用模型应留空；留空不会改用主模型，相关判断失败则跳过（沿用原路径）。对外仍不暴露概率分数。

当工具数超过阈值且开启工具收敛时，主模型调用前会先筛选候选：

1. **系统路由**（可选）：选出这一轮需要哪些连接器——查询中有区分度的词会强制命中，模型选择只能补充、不能拆掉强制命中。
2. **工具预筛**：默认用**标准匹配**（BM25 / 词项与中文 bigram，无需额外组件）。业务系统多或中英混用时，可在「**匹配与决策**」一键启用**增强匹配**（本机 Ollama 拉 `bge-m3`，或 Embedding API）；同页一键启用 **System One**（同一台 Ollama 拉 `tev1`，或 API）。增强匹配用 BM25 + 向量混合检索（RRF），失败则回退标准匹配。

操作台可看安装进度、本机程序 / 模型路径，自定义模型目录，并可选清理下载内容或卸载 Ollama 本体。

收敛只影响「这一步 prompt 里出现哪些 schema」，**不影响工具本身能不能用**：已注册的工具只要被点名仍会执行。没有任何命中时则回退为全量；系统工具与登录工具始终保留。

### 基准结果（可复现）

设置：**37** 条真实只读业务请求，横跨 **3** 个已接入的后台（共 **390** 个工具），模型为 DeepSeek-Flash；稳定性连跑 **5 轮（共 185 次请求）**。语料与脚本见 [`scripts/tool-routing-eval`](scripts/tool-routing-eval/README.md)。

| 预筛宽度 | 运行成功 | 平均实发工具 | 平均 turn-0 prompt | 相对宽度 32 |
|---|---|---|---|---|
| 32 | 36/37 | 43.1 | 4,703 | — |
| 24 | 37/37 | 37.4 | 3,980 | −15% |
| **16（默认）** | **37/37** | 30.6 | **3,090** | **−34%** |
| 12 | 37/37 | 27.1 | 3,033 | −36% |
| 8 | 35/37 | 23.6 | 2,600 | −45% |

直接下发**全量 390 个**工具时，turn-0 实测约 **8.5 万** prompt tokens；宽度 16 时实测约 **1.4k–3.8k**。连跑 **5 轮（共 185 次请求）**时，宽度 16 的运行成功率为 **99.5%（184/185）**；唯一一次失败来自无关工作流，而非工具不可用。宽度 8 时有两个多步请求失败。默认宽度为 **16**。

决策层为**可选项**、通过运行时设置热更新（出厂默认关闭）。上表衡量的是**工具筛选 + 预筛之后主模型 prompt 成本**（不是智能提速每一个子功能的全链路账单）。请和下表一起看：接上决策模型后，下列高频判断不再（或少）走生成式大模型，费用才会实际下降。

**哪些过程从大模型改成了决策模型**（需打开「智能提速」总开关与对应功能）：

| 过程 | 未接决策模型时 | 接上 System One（或其它低成本判定服务）后 |
|---|---|---|
| 要不要抽记忆 | 往往再调一次生成模型做抽取 | 先由决策模型判定；判「不值得」则整次抽取取消 |
| 这一轮偏哪些业务系统 | 全量工具 schema（或再用大语言模型来问） | 决策判定 + 预筛；主模型只看筛选后的 schema |
| 超大工具结果要不要留 | 常整段进后续上下文 / 摘要 | 先判定；无用则少喂主模型 |
| 自动路由偏轻量还是重量 | 启发式（或再用大语言模型仲裁） | 可选由决策模型做档位建议 |

宽度扫描脚本见 [`scripts/tool-routing-eval`](scripts/tool-routing-eval/README.md)。**上表（layer A）已是既有可复现结果，发版前已跑完；不必为接 System One 再扫一遍宽度。**

**判定服务对比（layer B，同语料 37 条、宽度 16、同机一次通跑）：**

| 判定服务 | 运行成功 | 命中期望工具 | 预筛召回 | 平均 turn-0 prompt | 端到端耗时 |
|---|---|---|---|---|---|
| **System One（本机 tev1）** | **37/37** | **31/37** | **37/37** | 4,435 | **~376 s**（约 10.2 s/条） |
| 备用模型（`deepseek-flash` profile） | 37/37 | 29/37 | 37/37 | 4,205 | ~556 s（约 15.0 s/条） |

事件里系统路由出处分别为 `systems_source=systemone`（126 次）与 `remote`（124 次）。主模型 prompt 同级（筛选宽度相同）；**端到端耗时约 1.48×**：把判定从大语言模型换成决策模型后，整批更快。原始汇总：`scripts/tool-routing-eval/out/layerB_compare.json`（本地产物，默认不入库）。

## 快速开始

**环境：** Go 1.25 或更高（与持续集成一致；不必装 C 编译器）、Node.js 20+（npm；Chat UI 经 `go:embed` 嵌入），以及一个 OpenAI 兼容服务的 API Key。

```bash
cp .env.example .env        # 然后填写 BAIZE_API_KEY=sk-...
```

```powershell
.\serve.cmd                 # Windows — web/chat 有变更时先重建 internal/ui/dist，再 go build
```

```bash
./scripts/serve.sh          # macOS / Linux — 同样会检查前端是否需要重建
```

- 操作台：http://127.0.0.1:8080/ui
- 跳过前端（沿用已有 `internal/ui/dist`）：`.\serve.cmd -SkipUI` / `BAIZE_SKIP_UI=1`
- 强制重建前端：`.\serve.cmd -ForceUI` / `BAIZE_FORCE_UI=1`

打开操作台即可发消息。如需更换模型、Base URL 或接入业务系统，把 `configs/config.yaml` 复制为 `configs/config.local.yaml`（已 gitignore）并修改，再用 `.\serve.cmd -config configs\config.local.yaml`（或 `./scripts/serve.sh -config configs/config.local.yaml`）启动。

## 用预编译二进制部署（无需安装 Go）

适合直接在服务器或本机跑正式环境。从 [GitHub Releases](https://github.com/rebornace/baize/releases) 下载对应平台的压缩包（含 `baize` 与可选的 `weixin-adapter`），解压后按下面配置即可。

**1. 准备目录（示例）**

```text
baize/
  baize                 # 或 Windows 的 baize.exe
  weixin-adapter        # 仅使用微信渠道时需要
  configs/config.yaml   # 可从本仓库拷贝样板
  .env
  data/
```

**2. 写 `.env`（密钥不进 YAML）**

```bash
BAIZE_API_KEY=sk-你的模型密钥
BAIZE_SETTINGS_KEY=一串足够长的随机字符
# 可选：BAIZE_LISTEN=:8080
```

**3. 启动**

```bash
# 在解压目录下（使用 configs/config.yaml）
./baize serve
# 或显式指定另一份配置：
./baize serve -config configs/config.local.yaml
```

操作台：http://127.0.0.1:8080/ui  

改端口、模型地址、数据库路径等改 YAML / 环境变量后**重启进程**即可，不必重新编译。连接器、账号等多数能力可在操作台配置，写入 `data/`。

Linux 用 systemd 托管、微信适配器独立部署等，见 [部署说明](docs/developers/deployment.md)。本仓库也可用脚本本地交叉编译：

```bash
# Windows PowerShell
.\scripts\build-release.ps1 -Version v0.3.0
# macOS / Linux
./scripts/build-release.sh v0.3.0
```
