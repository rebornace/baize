# Baize（白泽）

[![Go](https://img.shields.io/badge/Go-1.25-00ADD8?logo=go&logoColor=white)](https://go.dev/)

[![baize - Lightweight AI Agent Framework | Product Hunt](https://api.producthunt.com/widgets/embed-image/v1/featured.svg?post_id=1255168&theme=light&t=1789790934744)](https://www.producthunt.com/products/baize?embed=true&utm_source=badge-featured&utm_medium=badge&utm_campaign=badge-baize)

**给团队用的 AI 助手：能聊天、会调用你们已有的业务系统，重要操作可以先让人点头再执行——挂在现有服务旁边就能用。**

传说里白泽认得世间万物的名字。我们希望助手也能认清、用好你们业务里的接口和流程：看懂目标 → 去调用系统 → 需要时请同事在网页操作台确认 → 把结果写回对话或微信等渠道。业务侧一般**不用改代码**；有一份接口文档，助手就能真正动手。打开网页操作台，产品、运营和集成同学都能用。

---

## 为什么选白泽

- **接口文档变能力**：上传或指定常见接口文档（如 OpenAPI / Swagger），助手就能按接口办事，过程在操作台看得见。
- **重要操作先审批**：建单、改状态等，可要求同事在卡片上点「批准」或「驳回」后再执行，过程可追溯。
- **旁挂即用、停用干净**：单独跑一个服务，配置放在外面；停掉之后，业务系统几乎不留痕迹。
- **一个助手，多种入口**：网页操作台、告警/工单来信、即时消息等，共用审批、记忆和对外回复。
- **对方系统要登录也能接**：对话里点「浏览器登录」，或在设置里配置登录页；密码不经过大模型，登录后再去调业务。
- **能力可给常用 AI 工具接着用**：已接好的业务能力，可以提供给 Cursor、Claude Desktop、豆包等（只读）；登录过期时打开返回的登录链接即可，不要把密码贴进对话。
- **系统一多也不乱**：设置里可打开「匹配与决策」和「智能提速」，先帮助手收窄本轮该看哪些能力，主模型更省、更快（详见下方说明与开发者文档）。
- **按业务域分组**：财务、交易等系统可分成组；需要更强隔离时，可单独开一条子任务，审批互不影响。
- **接口变了看得见、做过的事能复盘**：重新导入接口后能对照「改了什么」；每轮对话旁可查看当时用了哪套模型与能力。
- **监控和日志就在操作台**：设置里可看运行情况与近期日志；支持常见监控与可选链路追踪；改观测相关选项不必改配置文件重启。业务出站也可配本机证书做加密连接。
- **长对话更稳**：对话太长会自动摘要；可选「长对话保留重点」；特别长的工具结果或粘贴可存成工作文件，对话里只留摘要；可记账号级要点、带附件。
- **工作区与账号**：侧栏可切换工作区；同一工作区内共享已登录的业务账号，工作区之间互不串号；对外提供给其它 AI 工具的身份与聊天账号分开。
- **能问白泽自己怎么用**：内置帮助技能（中英文），会指路到操作台对应页面，而不会擅自改配置或重启服务。

## 助手能做什么

### 对话与执行

- 默认按「思考 → 选能力 → 执行 → 汇报」推进；也可用技能包里的分步流程（可含审批点）。
- 操作台可**边跑边看**推理与调用步骤。
- 可切换多套模型；支持调节「思考」相关选项（视模型能力而定）。
- 新增模型时可**拉取服务端模型列表批量导入**，也可手动填一个模型。
- **技能包**：说明 + 可用能力。设置里勾选并保存，只影响新对话的默认起点；未勾选的仍可在聊天用 `@` 或 `/` 临时启用。登录类技能请按需 `@`，不要勾成默认。
- **工作区**：侧栏切换或新建；新对话落在当前工作区（暂不支持把旧对话挪到别的工作区）。
- 思考过程默认收成一行，点开再看；结束后用量会写在回复旁。

### 能力从哪里来

- **接口文档一键变能力**：每个接口进入列表，助手可直接调用。
- **小插件服务**：文档不全、或逻辑在文档外时，可自建一个小服务告诉白泽「有哪些能力、怎么执行」；也可回调到你们自己的地址由你们执行。
- **接入外部工具生态**：可接上支持 MCP 协议的工具服务（含常见授权登录）。
- **把能力导出给常用 AI 客户端**：在 Cursor、Claude、豆包等里直接用已接好的业务能力，不必再配一遍。登录失败时请用浏览器打开返回的登录链接。

### 人在回路与安全

- 敏感写操作可暂停，等同事在操作台确认后再继续。
- 需要登录时：打开登录页、先跳过该系统继续，或结束本轮。
- 能力可随时停用；完整密钥不会出现在对话回放里。
- 试用可用内置模拟模型（不必先准备云厂商密钥）；正式环境再配真实模型。

### 记忆、材料与长会话

- **记忆**：保存账号级要点，跨对话仍可参考。
- **定时任务**：人同意后，可设一次性、每天或每周指令；到点在原对话里自动开一轮。写操作仍走审批。设置里可管理自己的日程。
- **附件与文件存储**：本地或对象存储均可。
- **长对话**：自动摘要；特别大的内容可存成工作文件再分段查看；可选「保留重点」。
- 支持会话分叉、回退等日常操作。
- 网页登录身份按工作区共享；微信等渠道、以及「对外提供能力」的身份各自隔离。

### 消息渠道

告警、工单、即时消息等都可以接到**同一套**助手、审批与对外回复。

- **来信入口**：外部系统把告警/工单推过来，进入同一套流程。
- **即时消息**：仓库内正式支持**个人微信私信**；另有飞书、钉钉的参考示例，其它 IM 可按同样方式对接。
- 也可把事件推到你们自己的通知地址。

### 给产品、运营与集成

- 网页操作台支持**中文 / 英文**：对话、调用卡片、设置与运行参数。
- 「匹配与决策」「对外登录」「对外提供能力」「运行指标」「评测语料」等均在设置里可发现。
- 接口重新导入后能对照变更；聊天旁可查看本轮用了什么；导出给其它 AI 工具的调用有审计。
- 提供完整 HTTP 管理接口，可用脚本或平台对接，不强制某一种语言 SDK。
- 部分参数可热更新；默认本地数据库即可起步，需要时再换更大的库。

## 典型场景

**老系统旁边挂一个助手**  
服务已在线上、暂时不改代码：旁挂白泽，用接口文档把能力交给助手，内网先试「能查、能建单、能审批」，确认价值再谈改造。

**写操作必须人点头**  
助手可以查数、起草、建议；真正改状态、发指令时，同事在操作台确认，过程留痕。

**工具与渠道收拢到一台助手**  
外部工具、自研插件、来信、即时消息——同一套审批与记忆，少养一堆互不相通的机器人。

**多个业务域要分开管**  
把财务、交易等系统分组；真需要并行、互不影响时，再单独开子任务，而不是堆一棵复杂的「子代理树」。

**在 Cursor 等工具里复用已接好的业务能力**  
在白泽里接好接口与插件，配好登录页后导出；登录过期时打开链接即可，勿把密码贴进对话。请保证登录页地址对对方电脑/浏览器可达。

**接口会变、过程要留痕、内网要加密**  
重新导入后对照变更（并可发通知）；复盘当时用了哪套能力；出站可配证书，操作台可看监控与日志——不必另搭一套助手框架。

## 系统很多时，怎么更省、更快

接入的业务系统一多，若每次把全部能力都塞给大模型，会又慢又贵。白泽可以先做一轮**轻量判断**：本轮大概用哪些系统、哪些能力，再把收窄后的列表交给主模型。失败时会自动退回「全量」路径，保证还能用。

在操作台：**设置 → 匹配与决策**（可选增强匹配与本地/云端小模型帮做判断）→ **运行参数 → 智能提速**（打开总开关与需要的子功能）。只配判断模型、不打开开关，不会真正省主模型用量。

安装、参数与失败回退细节见 [开发者文档 · 架构](docs/developers/architecture.md) 与 [配置](docs/developers/configuration.md)。

### 实测（可复现）

在 **3** 个后台、共 **390** 个能力上，用 **37** 条真实只读请求测主模型首轮输入量；连跑 **5** 轮共 **185** 次。脚本见 [`scripts/tool-routing-eval`](scripts/tool-routing-eval/README.md)。

| 每轮交给模型的能力上限 | 成功 | 平均实发能力数 | 平均首轮输入量 | 相对上限 32 |
|---|---|---|---|---|
| 32 | 36/37 | 43.1 | 4,703 | — |
| 24 | 37/37 | 37.4 | 3,980 | −15% |
| **16（默认）** | **37/37** | 30.6 | **3,090** | **−34%** |
| 12 | 37/37 | 27.1 | 3,033 | −36% |
| 8 | 35/37 | 23.6 | 2,600 | −45% |

全部 390 个能力直接塞进首轮时，输入量约 **8.5 万**；默认上限 16 时约 **1.4k–3.8k**。连跑成功率约 **99.5%（184/185）**。用本地小模型做判断时，整批端到端往往比「再用一个大模型来判断」更快（同机对比约 1.5 倍量级）。完整对比与字段说明见开发者文档与上述脚本目录。

## 快速开始

**环境：** Go 1.25+、Node.js 20+（网页操作台会一并构建），以及一个兼容 OpenAI 接口的模型密钥。

```bash
cp .env.example .env        # 然后填写 BAIZE_API_KEY=sk-...
```

```powershell
.\serve.cmd                 # Windows
```

```bash
./scripts/serve.sh          # macOS / Linux
```

- 操作台：http://127.0.0.1:8080/ui
- 跳过前端重建：`.\serve.cmd -SkipUI` / `BAIZE_SKIP_UI=1`
- 强制重建前端：`.\serve.cmd -ForceUI` / `BAIZE_FORCE_UI=1`

打开操作台即可发消息。要换模型或接入业务系统：复制 `configs/config.yaml` 为 `configs/config.local.yaml`（已忽略进库），改完后用 `-config` 指定启动。

## 用预编译包部署（不必安装 Go）

从 [GitHub Releases](https://github.com/rebornace/baize/releases) 下载对应平台压缩包，解压后配置即可。

**1. 目录示例**

```text
baize/
  baize                 # Windows 为 baize.exe
  weixin-adapter        # 仅用微信渠道时需要
  configs/config.yaml
  .env
  data/
```

**2. 写 `.env`（密钥不要写进配置文件）**

```bash
BAIZE_API_KEY=sk-你的模型密钥
BAIZE_SETTINGS_KEY=一串足够长的随机字符
# 可选：BAIZE_LISTEN=:8080
```

**3. 启动**

```bash
./baize serve
# 或：./baize serve -config configs/config.local.yaml
```

操作台：http://127.0.0.1:8080/ui  

改端口、模型地址等后**重启进程**即可。多数业务接入可在操作台完成。Linux 托管与微信渠道部署见 [部署说明](docs/developers/deployment.md)。
