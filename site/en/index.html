Sit beside your stack. Turn APIs into abilities.

You usually don’t rewrite the business service. With an API document, the assistant can execute for real—visible and controllable in the console.

  • API docs become tools

    Import OpenAPI / Swagger and each operation joins the tool catalog; follow calls live in the console.

  • Approve sensitive writes

    Creates and status changes can wait for an operator to approve or reject—with an audit trail.

  • One assistant, many doors

    Web console, inbound alerts, and messaging channels share approval, memory, and outbound delivery.

  • Downstream login supported

    Sign in on a hosted login page (credentials never hit the LLM). Export wired tools over MCP to agents like Cursor; when auth expires, open the login link.

What major upgrades added

Beyond the Changelog: scale with many tools, see catalog drift, reconstruct what a run bound, and operate from the console.

  • Stay usable with many tools

    Matching & decisions one-click enables enhanced matching and the System One decision model. With Smart speed-up on, the main model sees a narrowed schema set; failures fail open.

  • Catalog changes are visible

    Connector re-import returns a CatalogDiff; optionally POST catalog.diff to events.webhook so API drift is alertable—no manual doc diffing.

  • Runs are reconstructable

    Each Chat run writes run.binding (model, knobs, tool-contract fingerprints). Open “View run binding” beside the assistant message.

  • Ops and compliance in the console

    Runtime metrics and recent logs in Settings; Prometheus /metrics and optional OTel; connector outbound mTLS via local cert paths; observability knobs hot-reload.

Get started

No Go toolchain required: download a release archive for your platform, set secrets, and start.

cp .env.example .env
# set BAIZE_API_KEY and BAIZE_SETTINGS_KEY
./baize serve
# open http://127.0.0.1:8080/ui
